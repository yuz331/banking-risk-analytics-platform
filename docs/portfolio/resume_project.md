## Claim-to-evidence check

| Wording | Repository evidence | Boundary |
| --- | --- | --- |
| Independent, AI-assisted prototype | Project scope and implementation artifacts | Personal project, not professional BA/security experience |
| 50,000 synthetic transactions | Seeded development run and reproduction commands | No real customer records or production bank integration |
| Four configurable rules | Config, detector modules and rule specifications | Illustrative criteria, not approved compliance thresholds |
| 79 passing tests | UAT record and test suite with dependencies installed | Functional evidence, not fraud accuracy |
| Persistent review history | Review schema/API, UI and new-session tests | Local aliases; no authenticated or tamper-proof audit log |

Measured fraud reduction, time savings, production throughput and stakeholder
approval are not supported by the repository. Keep wording tied to the evidence
and to the code/design you can explain in a live interview.
